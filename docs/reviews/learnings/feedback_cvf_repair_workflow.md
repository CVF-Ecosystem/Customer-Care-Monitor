## Evidence contract for the next execution

Each mutation record should include target/source baseline, expected and actual match count, applied diff or digest, test command, exit result, intended failing assertion, disposition (KILLED, SURVIVED, NOT_APPLIED or INCONCLUSIVE), restoration equality and post-restoration baseline result. A kill needs an applied relevant change, a runnable test and a failure tied to that behavior. Status labels alone do not prove a detector worked.

Continuity evidence should record the pre-edit role/phase acknowledgment, affected surfaces, validation/preflight result, any interruption and recovery, plus the final consistent state. Validate current prose as well as machine pointers; a gate pass only covers its implemented checks. The active SPEC, work order and immutable authority seed remain the execution authority; this learning does not widen scope, approve repair round three or override independent review requirements.

For test evidence distinguish PASS, FAIL, SKIP, NOT RUN and unresolved failures with reasons. Raw local logs may be temporary; commit reproducible commands and sanitized relevant assertions. Preserve limits such as capture environments using disposable MySQL even when the backend test suite was NOT RUN; avoid blanket statements that imply no DB was used at all.
