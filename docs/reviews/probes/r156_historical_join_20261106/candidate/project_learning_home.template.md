# Project Shared Learning Home

Memory class: governed-project-learning
Status: ACTIVE_REFERENCE

## Purpose

Keep reusable build/review findings in Git for every agent and the CVF parent.
Use case -> CVF -> use case; a local repair and a parent improvement have separate outcomes.

## Scope / Owner Boundary

Project orchestrator owns discovery and source records. CVF parent reviewer owns value/dedup/admission decisions. Project owner authorizes returned adoption. This folder grants no source change, API, pilot, deployment or parent implementation authority.

## Contract

Maintain this README as the record index; use LEARNING_RECORD_TEMPLATE.md. Empty inventory is valid: record no reusable finding yet rather than inventing a lesson. Read matching records before similar INTAKE, BUILD/REPAIR or REVIEW; do not reload all history. Add pointers in session memory/handoff and the project artifact catalog when a record becomes active. Preserve evidence/earlier failures and update an existing mechanism before creating a duplicate.

Every finding has trigger/context, project/source SHA, observed/expected, evidence confidence, mechanism or unresolved hypothesis, local action/result, value proposal, dedup owners, claim limits and separate project/parent/returned-application states. Secrets and customer payloads do not belong here. Provider memory may suggest a finding but cannot serve as governed proof.

## Value Filter And Feedback

A parent candidate needs a reusable mechanism and a concrete incremental benefit to an existing owner/control, supported by evidence or a clearly bounded design proposal. Explain rule gap versus application failure. Parent records accept/merge/defer/decline with reason; no automatic truth scoring or acceptance. A local repair does not close parent learning.

Link source record/SHA -> parent admission -> changed standard/template/checker and proof -> returned version/receipt -> project adoption and verification. Parent acceptance is not returned delivery, and returned delivery is not tested adoption. Parked project adoption stays PARKED_BY_OPERATOR even when parent work is done.

Machine intake stays at docs/learning_intake/<findingId>.intake.json via the pinned runner intake command. It is a generation-only exchange record, not the source journal or parent acceptance. A parent decision still requires parent admission evidence.

## Evidence Checks Before Claiming Success

- Cleanup: one shell end-to-end; resolved disposable boundary; prerequisites and exit codes checked individually; residual resources listed. A rejected command is not executed cleanup. Path-conversion workaround affects only its invocation, never approval.
- Negative tests: finite fixture/process budget; actual replacement count and applied diff; named intended behavioral assertion; byte restoration and passing restored baseline. NOT_APPLIED, INCONCLUSIVE, SURVIVED and KILLED are distinct. An unrelated error/timeout/build failure is not a kill.
- Coverage: separate enumeration/retrieval/store/checkpoint/local adapter/live-provider/governance layers with exact source/window/dataset. Record FAIL/SKIP/NOT RUN/timeouts; later or partitioned passes are separate evidence, not an explanation or erasure.
