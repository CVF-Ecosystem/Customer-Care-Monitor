## Root cause and repair boundary

`governance.yml` invokes `python -m unittest discover` before invoking the preflight. Python writes bytecode into the checked-out repository by default. The gate correctly includes untracked, non-ignored paths in its changed-file set, so the generated `.pyc` files make its own CI job fail. Local review used `python -B`, which prevented that side effect and did not expose this workflow-order interaction. The gate must continue to reject genuine out-of-scope files; hiding all untracked paths or broadening the authority seed would weaken the control.

Repair `GOV1-CI1` is bounded in the existing GOV-001 work order: make the governance job's Python executions avoid repository bytecode output (including test subprocesses), demonstrate a local clean-checkout-style sequence, then have Codex independently re-review and push the repair to the draft PR. A successful hosted rerun at the new head is required before the GOV-001 gate package can return to REVIEW_PASS. No product source, CVF parent, provider call, database data, merge, deployment or FREEZE is authorized by this finding.
