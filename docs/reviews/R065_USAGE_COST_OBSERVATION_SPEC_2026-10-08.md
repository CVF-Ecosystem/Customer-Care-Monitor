## Source audit and design decision

`backend/ai/provider.go` exposes AIResponse integer InputTokens/OutputTokens and response metadata, but no presence bit, verified invoice, pricing revision or provider retry/HTTP attempt accounting. Missing usage and reported zero are indistinguishable at this interface. `CalculateCost` returns a local estimate and known-price flag from mutable synced/static pricing; it does not certify actual billing. `backend/engine/analyzer.go` already calculates this once per successful SINGLE/BATCH response, writes AIUsageLog, then parses/publishes. Response+error follows the error branch and writes no usage. Existing source_execution records logical calls, errors/panics and usage-write outcomes, but no honest numeric observation.

Add a fixed aggregate `source_execution.usage_observation`; no new top-level Summary key, per-item/per-call metadata array, raw model/provider string, prompt/content, query, schema, price lookup or provider-interface change. Two exact observer calls consume already computed input/output/cost/known values immediately after existing CalculateCost. Existing calculation/log/write/errors/parsing/selection/admission/checkpoint/notifications stay byte-semantically unchanged. The nested aggregate shares existing tenant/job/run binding; invalid binding never introduces identifiers.

Version `ccmai.usage-observation.v1`, scope successful interface response/local estimate only. Fixed token presence/basis unavailable from interface, billing NOT_OBSERVED and pricing revision NOT_CAPTURED; optional totals are observation, not invoices or free-call proof. Zero interface values may sum to zero, but never certify that usage was supplied or a call was free. No raw model/provider retention; identity remains in existing logs only.

Only an active RESPONSE_RETURNED call may be observed once. New private guard prevents duplicate updates. No observations for error+response/error/panic before return/no work/setup failure. Checked nonnegative int64 token aggregation, checked finite/nonnegative cost and safe counter/float aggregation; negative/NaN/Inf/overflow are explicit invalid/overflow states and never break JSON serialization. Counts distinguish observed responses, invalid token pairs, known/unknown price and invalid estimates; no silent wrap or truncation.

Totals are all-or-nothing for the observed begun-call prefix: token pointers null unless callsBegun>0, each begun call observed and every token pair/total valid; estimate pointer null unless those conditions plus every price known and estimate/total finite/nonnegative. Completeness flags false for no-call, missing/error/interrupted/in-flight calls, invalid/overflow or unknown price as applicable. Completeness covers only the begun prefix, not future calls, complete job coverage, real provider usage presence or billing. Successful zero pairs remain interface observations with presence unavailable.

Freeze copies optional numbers independently; retained-call trimming does not lose aggregate coverage. Fixed envelope must preserve the existing 1500-byte execution freeze test and global128KiB receipt cap. Initial/progress/final/early/panic/fallback Summary paths already use execution.freeze, so nesting propagates without changing composer/signatures. Usage-write failure/panic does not erase already observed values; existing usage_writes separately reports actual write outcome. Stored prefix is distinct from returned terminal receipt.
