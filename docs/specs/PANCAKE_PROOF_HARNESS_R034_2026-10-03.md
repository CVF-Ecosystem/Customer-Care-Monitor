## Objective and design

Build a standalone offline harness that exercises the existing Pancake adapter with an injected in-memory HTTP transport, bounds all attempts/time/response sizes, reconciles an independently specified synthetic inventory and emits sanitized evidence. This tranche prepares reusable tooling; it neither executes a channel request nor certifies CVF AI governance. No existing adapter, engine, backend service, dependency or frontend behavior changes.

Implement additive `backend/channels/pancake_proof.go` with corresponding tests. Being in the channels package allows a dedicated proof-only adapter instance to receive a custom client without editing `pancake.go` or its default behavior. Add an offline CLI at `backend/cmd/pancake-proof/main.go` with tests. Use standard library/existing dependencies only. Public names/data schemas are worker design choices within the requirements below; document stable options, receipt schema and exact commands in BUILD evidence. No flags to read a real credential, select live mode, use a database or download media in the R034 CLI.

The library may accept credentials and an explicitly supplied transport as in-memory arguments for a later authorized caller. It must never discover credentials, consult application config or fall back to `http.DefaultTransport`; missing transport is rejected before adapter work. R034 calls/tests supply synthetic values only. CLI always uses its own deterministic finite in-memory transcript transport; configuration must not select a network transport or endpoint base override. Synthetic payloads are legitimate adapter/harness contract tests, not live or AI-governance proof.

Design constraints: raw inventory/transcript values remain in memory and synthetic fixtures during this BUILD. A later live caller must separately supply authorized credentials, independent inventory, stable HMAC key and transport under a new work order; this library is not an approval authority. Inventory visibility/retention/quiescence and real provider timestamp/protocol compatibility remain unknown. No persist/checkpoint/dispatch behavior is demonstrated anew by this adapter-only harness.

## Evidence and negative controls

Each PH requirement maps to named committed tests, exact commands and observed assertions in BUILD evidence. Add focused failure cases across library and mounted CLI entrypoint, not only direct internal helper tests. Use complete fake transcripts with a hard finite ceiling before indexing, no external fallback, and explicit attempted-request observers.

Apply at least six finite semantic mutations: bypass host/path admission; permit redirect following; omit shared request counting (or exclude retries/second run); bypass deadline enforcement; turn a missing-ID reconciliation into PASS; leak a raw error or identifier into the receipt. Name the assertion expected to detect each; restore byte identity in finally and rerun baseline. Build errors, fixture panic, timeout and a unrelated competing guard are INCONCLUSIVE rather than semantic kills. No old-source mutation is required for entirely new files; baseline absence is not a behavioral detector.

Required local verification: new library/CLI tests uncached, complete channels tests, race for new packages if toolchain supports it (otherwise explicit NOT RUN reason), `go -C backend build ./...`, `go -C backend vet ./...`; docs build, catalog/doctor, diff and default/PR/complete-changed-set preflights plus gate unit tests. No DB fixture or full DB-dependent engine suite is required for these additive files; those checks are NOT RUN, with inherited local product evidence kept separate. Do not trigger dependency downloads or other external network under this order; use installed caches or report prerequisite block.

Acceptance is offline harness REVIEW_PASS only after independent Codex review of exact Claude BUILD and seed timing/identity, all PH requirements, mutation sensitivity and preserved original sources. No self-approval or FREEZE. A defect needing existing adapter/engine/dependency changes is BUILD_BLOCKED with a concrete separate scope proposal.
