## INTAKE and DESIGN decision

The analyzer treats every positive limit as a test run and forces `excludeAnalyzed=true`, including explicit full reruns. Dates are parsed as UTC; invalid values silently disappear, lower comparison is strict `>` and message snapshots inherit the lower time cutoff. TriggerJob accepts unknown modes and malformed/negative limits by falling back, and ignores dates on nonconditional modes. Explicit-mode evaluation lookups use arbitrary JobResult rows with incomplete tenant scope; since-last logs lookup errors then falls back. Nonordinary unlimited runs can overwrite the ordinary checkpoint at finish. The UI calls conditional mode without stating that already analyzed conversations are re-evaluated, retains a hidden limit between modes, and requires both date endpoints although the backend accepts one-sided ranges.

Separate **mode**, **candidate bounds**, **count cap**, **snapshot scope** and **checkpoint policy**. Keep public method signatures and HTTP mode names. An internal typed plan/helper is preferred; do not infer mode from the cap. Date controls select conversations by `last_message_at`; selected conversations use the full local snapshot, so preceding context is included in analysis. This can increase transcript length and repeat analysis under an explicit rerun. Only ordinary unlimited incremental execution owns `last_run_at`; explicit reruns and test runs leave it unchanged even when unlimited. No schema or new persisted mode field is needed.

## Mode matrix (normative)

| Entry / mode | Candidate policy | Positive cap | Snapshot | last_run_at |
| --- | --- | --- | --- | --- |
| RunJob / ordinary RunJobWithProvider with zero cap | Accepted R025 source-version eligibility across tenant/input channels | Not applicable | Exact full prepared snapshot; unchanged skips | Accepted R025 scan-start checked write |
| RunJobWithLimit / positive-cap RunJobWithProvider (test run) | Last-message strictly after captured run-start minus 7 elapsed days; no conversation_evaluation for this tenant/job/conversation | Caps after eligibility, deterministic order | Full local | Preserve |
| RunJobFull / conditional RunJobFullWithParams | All tenant/input-channel conversations; optional VN date bounds on last_message_at; include already evaluated/unchanged | Caps after bounds, never switches to unanalyzed | Full local | Preserve |
| RunJobUnanalyzed / unanalyzed | No conversation_evaluation for this tenant/job/conversation, all dates | Caps after eligibility | Full local | Preserve |
| RunJobSinceLast / since_last | last_message_at strictly newer than greatest non-NULL last_message_at of a conversation evaluated by this tenant/job **within current input channels**; if no non-NULL anchor, use unanalyzed all-date policy | Caps after eligibility, no implicit unanalyzed switch when anchor exists | Full local | Preserve |

All explicit-mode candidate queries are tenant/input-channel scoped and ordered by `last_message_at ASC, id ASC` (MySQL NULL-first ordering is acceptable and must be tested). Date-bounded/since-last/test candidates with NULL last_message_at do not qualify. Unbounded full/unanalyzed may include NULL candidates; empty snapshots cause zero analysis, not a fabricated evaluation. A cap is a conversation count, not a guaranteed provider-call count (batching/empty source may reduce calls). No cap is introduced on ordinary incremental scans. Capture the test-window clock once; no moving time.Now predicates.

Evaluation membership means `result_type=conversation_evaluation` joined through job_runs with tenant/job identity and conversation tenant/channel identity. PASS, SKIP and classification evaluations count as evaluated, even without issue findings; a finding-only row, other job/tenant or orphan snapshot does not. Legacy evaluation without snapshot still counts for these explicit modes; preserve R025's distinct source-version/provenance rules. An anchor query returning no value must be distinguishable from a failed query. Selection/anchor errors return non-success; never silently broaden or report empty success. Since-last is an intentional event-time cursor: it does not cover older unevaluated, equal-timestamp or backdated late source; use unanalyzed/full or ordinary incremental for those. No immutable historical anchor or automatic rule-version invalidation is promised.

## Date and request admission contract

1. `from`/`to` are strict date-only `YYYY-MM-DD` calendar keys in Asia/Ho_Chi_Minh, independent of browser/server timezone, language and inactive tenant timezone setting. Public inclusive bounds become typed `[fromMidnight, midnightAfterTo)`; missing sides stay open. Equal dates select one day. Malformed/impossible/reversed/nonrepresentable dates produce 400 `invalid_date_range` before config resolution or worker dispatch; direct engine calls return an error before JobRun/activity/provider resolution. Preserve R026 actual-instant extrema behavior, including UTC year-0999 rejection and overflow of a supplied inclusive final-year `to`.
2. Reuse the accepted R026 parser semantics through a shared `backend/pkg/business_dates.go` helper with a thin handler adapter. Preserve all existing report call sites and R026 tests; avoid an engine-to-handler import cycle or diverging parser copies. Typed query bounds must be proven with MySQL driver loc=UTC and loc=Asia/Ho_Chi_Minh; do not hand-format UTC strings, migrate timestamps or change DSNs.
3. Trigger mode is one of `unanalyzed`, `since_last`, `conditional`. Omitted mode defaults to since_last; omitted mode plus `full=true` aliases conditional (including unbounded full rerun for compatibility). Reject unknown modes; reject `full=true` with an explicit nonconditional mode. `full` is absent/empty/true/false, otherwise invalid. `from`/`to` are permitted only for conditional; reject supplied nonempty dates on other modes rather than ignoring them. Existing UI's requirement of at least one conditional bound/cap is retained, while API/direct RunJobFull keeps unbounded full compatibility.
4. HTTP `limit` absent/empty/zero means unlimited; otherwise a representable decimal nonnegative integer. Reject negative, fractional, signed-plus, whitespace, overflow and nonnumeric strings with 400 `invalid_run_parameters`; leading decimal zeroes may be accepted. Modes/full conflicts also return this bounded error. Direct engine negative caps reject before any side effect; test-only RunJobWithLimit requires a positive cap. Invalid requests must create no run/activity, resolve no provider/config and launch no worker. Tenant job-not-found/permission behavior remains intact; do not change auth policy.
5. JobDetail states that conditional mode re-evaluates already analyzed conversations and dates select last-message days in Vietnam while retaining full conversation context. Explain since-last's older/equal-timestamp omission. Permit valid one-sided date controls and equal-day pairs. Prevent invalid/noninteger/negative UI limits from dispatching; hidden conditional limits must not leak into other modes. Clearing a limit means unlimited. Retain the at-least-one-condition guard for the conditional UI and existing API route/store contract. Date-only requests must be browser-zone independent. Narrow dialog copy/validation changes only.

## Terminal bookkeeping

Explicit modes preserve last_run_at on zero-work, success, partial/error, cancellation and persistence failure, whether capped or unlimited. Update terminal run fields and last_run_status/updated_at with tenant-scoped checked persistence, using the existing verified transactional finalizer where suitable, without a checkpoint argument. Observe context cancellation even in the final/only provider call or empty selection; honor an already stored cancelled status. Failed terminal persistence must return an error and must not emit completed activity/notification or pretend success. Do not redesign run ownership, jobCancelFuncs, cancellation registration or scheduler; those are F06. Existing R025 ordinary selection, exact sent/saved snapshots, source-integrity checks and checkpoint tests remain unchanged. Notification transports are untouched and disabled in fixtures.
