## Intake and design

The R034 integration packet identifies absent independent inventory loading. Current CLI builds both a finite synthetic transcript and independently written expectations in buildFixture. Add optional `-inventory PATH` to load a caller-authored synthetic expected inventory for the existing pass transcript. Without the flag preserve every existing scenario/CLI behavior. With the flag permit omitted/default or explicit `-scenario pass` only; reject other scenario combinations before opening the file. Replace only the expected inventory, never derive HTTP responses from it. Page/token/since/transport remain existing synthetic constants; no live mode, endpoint override or environment/config discovery.

This is a bounded offline integration slice. A caller-supplied provenance label does not establish independently verified live inventory or quiescence. Actual inventory/capture/credential input, exclusion manifest, live transport/pacing/capture/receipt provenance remain separate future contracts. Production adapters, proof library/options/receipt schema and engine stay unchanged. Avoid retargeting historical baselines or editing R040 closure records.

## Wire contract

Exact schema `pancake-proof-synthetic-inventory/1`; UTF-8 JSON object with required `schema_version`, `evidence_type` (exact SYNTHETIC_OFFLINE), `provenance` (safe existing proof-label characters,1..64, synthetic- prefix), `page_id` (exact synthetic-page-001), `conversations` (array, may be empty). Each conversation requires `id` (syn- prefix plus existing safe segment rules), `updated_at` (nonzero RFC3339/RFC3339Nano with explicit Z/offset), `messages` (array). Each message requires `id` (syn- prefix, nonempty/unique per conversation), `sent_at` (same instant rules), `sender_type` (customer|agent), `content_type` (text|attachment), `attachments` (array). Each attachment requires `type` (image for this fixed pass fixture) and `name` (nonempty,<=256 UTF-8 bytes, no control characters). Conversation/message IDs <=128 bytes. Required fields must appear exactly once at each object; reject unknown/duplicate keys, wrong types, null required values, invalid UTF-8, trailing JSON/nonwhitespace, missing/unsupported schema/evidence, unsafe identifiers and duplicate row IDs. Use explicit wire structs/conversion, not implicit encoding/json field matching to exported Go inventory structs.

Input ceiling1MiB,100 conversations,1000 total messages,16 attachments/message, maximum JSON nesting64. Bound reads to at most ceiling+1 bytes even if stat is stale/file grows; reject extra byte, never truncate/accept prefix. Only explicit local regular file; reject directory, symlink/reparse/network-share/URI/device/pipe inputs before opening where detectable. No stdin, URL fetch, includes, environment defaults, glob or directory discovery. Return fixed sanitized errors; never echo file path, JSON/parser/OS error details, IDs/names or input bytes. No raw captures/output files or persistent writes. Tests may use task-owned synthetic temp files only.
