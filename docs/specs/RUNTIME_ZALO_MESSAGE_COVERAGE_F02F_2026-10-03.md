## INTAKE and DESIGN

Source inspected at `59a88d96fa23b80803eef158ca9f415f1f003240`: `backend/channels/zalo_oa.go` FetchMessages treats missing/null/wrong-shaped data as empty, skips nonobject rows, float-converts timestamps, stringifies arbitrary message IDs, accepts unvalidated direction, stops at short pages and has no finite page budget. It intentionally ignores since. Shared request handling already bounds bodies/status and sanitizes errors after R024; preserve it. `backend/engine/sync.go` discards messages returned alongside an error, continues peer conversations, records partial and withholds checkpoint/after-sync; verify this behavior without editing engine source. These are inspected mechanisms, not reproduced defects or real-channel incidents.

Primary reference retrieved 2026-10-03: [official Zalo conversation API](https://stc-developers.zdn.vn/docs/v2/official-account/tin-nhan/quan-ly-tin-nhan/lay-thong-tin-tin-nhan-trong-mot-hoi-thoai?lang=vi&ts=1773705600080). It confirms GET `/v2.0/oa/conversation`, authenticated header, JSON query, count up to10, offset indexing from the latest message, string message IDs and src0/1. Its example uses millisecond time. Direct canonical-page retrieval returned only the shell; indexed official reference supplied the content. No complete exhaustion, stable-snapshot or attachment-schema guarantee was retrieved. Historical R024 source assumptions remain explicitly inherited.

Design decisions: count10; absolute offsets advance by physical rows; explicit valid empty array is the application terminal rule. Short nonempty pages continue. Preserve full-history/no-since-filter semantics for analyzer context, including old messages and replay updates. Deduplicate exact repeated rows by message ID; conflicting rows with the same ID fail rather than silently choosing uncertain content. Preserve current text, direction and attachment mapping; link strings documented upstream versus current object-link mapping are a separate compatibility question, not silently migrated. Use message-only request/redirect protection; do not modify shared request/refresh behavior. Snapshot instability, retention, visibility, rate limits and actual provider terminal behavior stay OPEN; conservative errors may prevent completion if live responses differ.
