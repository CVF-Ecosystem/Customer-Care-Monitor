## Local behavior contract

1. Initial GET uses `https://graph.facebook.com/v21.0/{escaped-conversation-id}/messages`, existing fields `id,message,from,to,created_time,attachments,shares,sticker` and limit100. Reject blank conversation identity without sending a request. Preserve local configured page-token authentication; never trust credentials carried by a next link. Only output filtering uses since; no unverified upstream since/until parameter.
2. Every page must be a JSON object with an explicit data array. Require every row to be an object with a nonblank string ID and parseable nonzero created_time using the existing Graph timestamp contract. Validate rows before dedupe or since filtering, including old/repeated rows. Preserve optional content/sender/attachment/sticker/RawData mapping semantics; no expansion of retained payload or new redaction claim.
3. Validate paging even on an empty or short page. Absent paging, or a valid paging object without next, is local terminal evidence after final context check. Present null/non-object paging or null/non-string/empty next fails closed. Empty data WITH a valid safe next must continue. Do not transplant Pancake's explicit-empty terminal/nonprogress rules into Graph.
4. Follow only absolute HTTPS URLs with hostname graph.facebook.com, no userinfo/fragment and no port except absent/443, exact v21.0 message path for this conversation (compare escaped path safely). Reject other conversations, conversation-list endpoint, versions, hosts, relative/non-HTTPS/protocol-relative links, malformed query and encoded path traversal. Validate BEFORE any request/token transmission. Message-only helpers are permitted; accepted conversation validator unchanged.
5. Strip provider-supplied access_token values and inject the configured token once for every actual request. Detect repeated canonical path/query identities independently of auth-token values, host default-port spelling and query order/encoding; seed the initial page identity. Preserve legitimate non-auth pagination parameters. A duplicate-only or empty page may continue on a distinct safe next; message IDs alone do not prove cursor nonprogress. Repeated URL/cursor identity fails; endlessly changing distinct links hit the page budget.
6. Use a message-only request path preserving injected transport and timeout, rejecting all redirects BEFORE following Location (including same-host redirects), rejecting non-2xx including non-JSON HTTP failures, bounding each response at 8 MiB before decode, closing response bodies and honoring context cancellation. Explicit Graph error objects remain non-success. No retry policy added. Do not change shared doRequest, HealthCheck, conversation behavior or client-global redirect policy. A per-message client copy/helper may contain these controls.
7. Deduplicate exact IDs, retain first-seen mapping, filter inclusively SentAt >= since (zero since retains all) and return ascending SentAt with stable first-encounter ties. Do not stop at an older row or infer a global provider order. Preserve identity/time meaning; no DSN/timezone/storage migration.
8. Cap traversal at 500 logical requests/pages. Terminal page500 succeeds; page500 with another next fails without request501. Check context before request and before accepted terminal return; cancellation must remain errors.Is-recognizable. Export distinct ErrFacebookMessageCoverageIncomplete for shape/row/paging/cycle/budget failures, preserving R022's conversation identity. Return non-nil on transport/HTTP/decode/size/Graph failure; partial slices are diagnostic only. Errors use fixed classes/page numbers, never raw URLs, body, IDs or credentials. Existing analyzer/checkpoint ownership semantics must consume this non-success correctly without engine source edits.

More traversal and conservative failures can increase request cost or reject histories exceeding budget. Nil-error means the local validated next-link contract completed under fixture assumptions; it does not prove live visibility, permission, retention or snapshot stability. Existing shared helper/other caller and attachment-download surfaces remain outside this bounded message repair; no general adapter security certification is claimed.
