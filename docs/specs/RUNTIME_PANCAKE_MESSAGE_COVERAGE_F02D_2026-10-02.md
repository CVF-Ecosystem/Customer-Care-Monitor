## Endpoint evidence and DESIGN decisions

Primary source: [Pancake official OpenAPI](https://developer.pancake.biz/openapi/openapi.yaml), retrieved unauthenticated on 2026-10-02 via Python urllib after the web reader could not open YAML. HTTP documentation retrieval only; no channel API or credentials. Retrieved bytes: 175390; SHA256 `1692045af3c4c58b71471f6b52403c1ad748e7fd77cd26834d17bf8160650c71`.

The GET `/pages/{page_id}/conversations/{conversation_id}/messages` uses public API v1, optional `current_count` as an index position returning the preceding 30 messages, and page access token authentication. `MessagesResponse.messages` is an array described as newest to oldest; message identity is a string and `inserted_at` a date-time string. The schema does not mark these properties required or establish an immutable snapshot, cursor, total count, empty-page terminal guarantee or concurrency contract. It describes an optional boolean `success`. These are documentation facts, not observed live behavior.

Local safety decisions:

- Preserve GET endpoint/authentication and the existing request helper's bounded retries, throttling, context and 8 MiB response limit. Omit `current_count` initially; subsequent positions equal cumulative physical rows consumed, including duplicates and rows outside `since`. Retries reuse the same position.
- Require an explicit valid empty `messages` array for local nil-error completion. Missing/null/wrong-type arrays cannot establish coverage. Preserve compatibility with absent `success`; explicit false remains failure and a malformed non-null success value must fail. Do not infer success from HTTP 200 alone.
- Traverse beyond short pages and older-than-since rows. Do not rely on the disputed within-batch source comment or on cross-page ordering for early termination. `since` filters output only, inclusively. No new `until` parameter or provider snapshot claim.
- Nonempty duplicate-only/nonprogress pages fail closed. Overlapping pages with new IDs may continue, but the fixed 200 logical-page budget still bounds traversal. An empty page consumes one slot; no request 201 is allowed.
- Return messages sorted ascending by parsed `SentAt`, stable by first-seen encounter order for equal timestamps. Deduplicate by exact ID, retaining first-seen mapping. Validate every row before filtering/deduplication, including old and repeated rows. Preserve existing time parser semantics; no timezone/storage migration.
- Export a separate `ErrPancakeMessageCoverageIncomplete` identity for contract/shape/nonprogress/budget failures; keep R023's conversation error identity unchanged. Diagnostic messages must use fixed classes/page numbers, never raw provider text, payloads, IDs, credentials or token-bearing URLs. Cancellation must remain recognizable through `errors.Is` when wrapped. Transport/API failure remains non-nil with existing sanitized behavior. Returned partial slices are diagnostic, never an accepted message window.

Full traversal may cost more requests and conservatively fail large histories or unstable offsets. That is an explicit bounded safety trade-off. Explicit-empty completion establishes only this local traversal contract under the fixture's assumptions; offset insertion/deletion can still skip data in a changing live history. This tranche cannot prove a complete live snapshot or lift global F02 OPEN.
