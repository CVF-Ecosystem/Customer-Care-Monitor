# CCMAI-GOV-001 — downstream machine-gate contract

Status: SPEC accepted for bounded WORK_ORDER. Date: 2026-09-30. Risk: R2. Authority: [applicability decision](../decisions/CVF_DOWNSTREAM_GATE_APPLICABILITY_2026-09-30.md), `.cvf/manifest.json`, `.cvf/policy.json`, `AGENTS.md`, and the active session state. This governs repository workflow; it is not application AI governance proof.

## Required behavior

1. A single documented, fail-closed local preflight command runs portable static checks for manifest/policy/workspace paths, continuity, active/new work-order and role contract, BUILD/review/claim boundary, catalog freshness, and bounded changed-file secret hygiene. It exits nonzero on malformed or missing required input. It supports a PR base/head or explicit changed-file mode without trusting uncommitted files in CI. Diagnostics identify fields and paths but never print credential values.
2. Continuity gate reads the canonical active state and its named handoff, an explicit small machine-readable front marker in `CVF_SESSION_MEMORY.md`, and `IMPLEMENTATION_STATUS.currentPhase`. It compares mode/phase, handoff, active role, next move and parked checkpoint where those values are declared. It checks that phase belongs to the manifest model and that all resolved paths stay inside the project. Missing optional compact bootstrap model is a nonblocking `BOOTSTRAP_MIGRATION_PENDING`; if present it must match canonical values. A stale WORK_ORDER memory/status pointer against REVIEW must fail, as must a missing or escaped handoff.
3. Prospective work orders and return/review packets have a documented small structured contract. It binds tranche ID, status/phase, risk ceiling, worker/reviewer/commit owner, allowed paths and effects, BUILD commit, review evidence and terminal disposition as applicable. Enforce on changed active work orders and current tranche, not all historical files. R2 worker self-review, an unauthorized path, a missing review for `REVIEW_PASS`, a BUILD receipt claiming FREEZE, or a `FREEZE` without settled review must fail. A local review may explicitly be `FREEZE_OPEN` and parked.
4. Claims of CVF governing AI/agent behavior require a real-provider receipt with request/response evidence, in line with `AGENTS.md`. Static/synthetic test evidence cannot satisfy that field. F08 may say `local gate REVIEW_PASS`; a claim that GitHub Actions has verified it requires a real Actions run URL, commit SHA and successful conclusion. Gate logic must not claim to verify an external run merely from a typed string; Codex independently checks the run through GitHub after PR.
5. A bounded secret gate rejects newly tracked `.env` variants, private key files and recognizable credential literals in changed files, with documented false-negative limits and focused synthetic fixtures. It must not print matched values or read local ignored secrets. Local CI MySQL credentials created at runtime remain allowed. No Alibaba key or other secret may enter the repo.
6. GitHub PR checks invoke governance preflight and catalog, frontend `npm ci`, tests and build, existing docs build, and existing backend MySQL five-sentinel test/build on relevant paths. Governance workflow triggers on all authority/doc/tool/workflow paths and preferably every PR to prevent path-filter bypass. Explicit permissions are read-only except the existing docs deploy job on main; no PR deployment. Trigger tests or static assertions prove that each changed path class reaches a relevant workflow. Do not weaken the R019 parser or DB tests.
7. The package is usable on Windows locally and Linux GitHub runners without a mutable sibling core. If a pinned public core checker is actually invoked, pin and verify its SHA, prove that its downstream contract is satisfiable, and state its scope. Otherwise implement a small downstream adapter derived from the core control families, with source references and focused tests; do not claim copied core gates are running when they are not.

## Acceptance evidence

- Positive run on current clean project and on the PR runner, with each gate name/result; catalog check, frontend tests/build, docs build, backend real-MySQL gate remain independently visible.
- Negative tests for each critical control above, especially the two observed continuity drifts, R2 self-review, missing review/claim receipt, path escape, and forbidden credential files. Tests must show a baseline pass and mutation failure; tests that only echo implementation conditionals are insufficient.
- Exact changed set, `git diff --check`, isolated test fixtures, no credential output, no product/DB/provider/network side effects beyond CI package download and disposable MySQL.
- Independent Codex source/evidence review before PR; PR Actions result is recorded after actual GitHub run. No FREEZE, deployment or claim of runtime CVF control follows from this tranche.
